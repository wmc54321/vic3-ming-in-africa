# “大洋国—汉洲联省共和国”兼容性调查与实施计划

状态：调查完成；列为未来可选实现，当前延期且未排期，尚未修改模组实现。除非用户以后明确重新作出实施决定，否则不要开始编写兼容补丁、生成器或三方正统逻辑。

调查对象：Steam Workshop 项目 `3464386853`，本地元数据显示名称为“大洋国-汉洲联省共和国”。本次检查基于本机 2026-07-27 更新的订阅快照；该快照的 metadata 没有填写版本号或受支持游戏版本，因此只能结合用户给出的 Workshop 标题中的 `1.13` 与文件实际内容判断。后续开发必须重新校验订阅快照，不能把本次文件哈希和结构永久当作上游接口。

## 结论

有条件可行，但当前两个模组不能直接稳定共载，也不能只靠调整加载顺序解决。

- “可进入游戏、两国都按各自设定开局”的技术兼容，工程可行性高。
- 最稳妥的交付形式是一个独立、可选、最后加载的兼容补丁，而不是把汉洲专用逻辑写进非洲大明本体。
- “大明、汉洲、大清三方都拥有完整且互相承认的中华正统路线”属于第二阶段设计功能，工程量和叙事决策明显高于基础兼容。
- 在获得对方作者授权或明确许可前，不发布包含对方完整州历史衍生文件的 Workshop 成品；可以先完成本地生成器和可重复验证原型。

本文件以下阶段均为备选方案，不代表已批准的开发任务。当前决定是保留非洲大明的独立游玩方式，不实施兼容层；未来若重新启用，优先从独立可选兼容补丁的本地 MVP 开始。

## 已确认的硬冲突

### 1. 开局州历史互斥

双方都提供：

- `common/history/states/00_states.txt`

非洲大明还在两个 descriptor 中声明：

```text
replace_path="common/history/states"
```

这会使汉洲的州历史无法和非洲大明的州历史自然叠加。任取一份文件都会破坏另一方开局：

- 采用非洲大明版本：`DAY` 的汉洲开局州及其新增州历史缺失。
- 采用汉洲版本：`MGN` 没有非洲开局领土，也没有生成器加入的桥接文化 homeland。

本地静态审计结果：

- 原版 1.13 州历史有 675 个州块。
- 汉洲快照有 690 个州块：新增 17 个州，移除原版东西新几内亚 2 个州，净增 15 个。
- 汉洲开局拥有 26 个州块。
- 非洲大明开局拥有 92 个州块。
- 两组开局州没有重叠。
- 汉洲相对原版改变省份集合的 7 个既有州都位于澳洲/大洋洲；非洲大明的 92 个州中，省份集合变化为 0。

因此冲突是“同名整文件覆盖”，不是双方争抢同一块土地。以汉洲州历史为输入，再机械施加非洲大明生成器的非洲所有权和 homeland 变换，是可行的合并路径。

### 2. 可成立国家定义互斥

双方都提供：

- `common/country_formation/00_formable_countries.txt`

汉洲相对当前原版的有意差异是：

- 移除 `AOT`。
- 移除 `AST`。
- 从 `IDN` 的州列表移除 `STATE_WESTERN_NEW_GUINEA`，与其地图改造一致。

非洲大明的关键差异是给 `CHI` 增加限制，阻止中华特许公司自行成立中国。兼容版本必须同时保留上述两组差异，并以当前 1.13 原版为共同基线重建；不能任选一方整文件。

审计还发现非洲大明当前文件把 `FSA` 的条件从原版 `has_law_or_variant` 改成了 `has_law`，但现有实施文档没有把它列为预期差异。制作兼容文件前应先单独确认这是有意修复还是上游漂移，不能顺手带入兼容补丁。

## 已确认的低冲突部分

- 双方自定义国家 tag 没有撞名：非洲大明使用 `MGN`、`MCC`、`MDC`、`MKC`、`MLF`、`MSB`、`MCA`、`MJP`、`MSE`；汉洲使用 `DAY`、`XJ*`、`HZN` 等。
- 自定义文化、法律、建筑、事件 namespace 和本地化 key 未发现直接撞名。
- 两边中英文 localization key 的交集为 0。
- 建筑和人口历史按地区分文件：非洲大明覆盖 `03`、`04`、`08`，汉洲覆盖 `12`、`13`，没有同路径文件冲突。
- 军事编制文件名不同；国家历史文件名和 tag 不同。
- 汉洲对印尼/澳洲 state region、战略区域和地图资产的修改不会直接改变非洲大明 92 个开局州的省份边界。
- 非洲大明当前所有显式公司州 key 在汉洲州历史中仍存在；汉洲移除的东西新几内亚不在当前八家特许公司的显式范围内。

## 需要实机确认的共享挂钩

双方都向 `on_monthly_pulse_country` 注册子 on_action：

- 非洲大明：`mgn_company_monthly_pulse`
- 汉洲：`DAY_monthly_events`

子项名称不冲突，写法也符合以共享入口挂接独立子项的常见模式，但静态扫描不能替代引擎验证。兼容测试必须确认两个每月子项都会触发，且错误日志没有 duplicate/overwrite 警告。若加载顺序导致其一丢失，兼容补丁需提供一个显式聚合入口。

## 语义冲突与兼容边界

### 中华正统路线

非洲大明的核心路线把 `MGN` 与 `CHI` 定义为“两中国”；汉洲的北伐和恢复山河路线也把 `CHI` 作为主要对手，但完全不知道 `MGN` 的存在。

直接共存时可能出现：

- `DAY` 吞并 `CHI` 后，非洲大明现有判断可能把“大清不存在”解释为 `MGN` 已经胜出，即使中国本土实际由 `DAY` 控制。
- 汉洲事件叙事把元、明、清作为崖山之后的历史王朝讨论，不会回应仍在非洲存续的大明朝廷。
- 两边都能围绕中国本土推进互不知情的战争、宣称和日志，脚本未必报错，但叙事结果可能互相矛盾。

推荐把兼容范围分两档：

1. 基础兼容（首个 MVP）：保证两国正确开局、地图和各自系统能运行；汉洲暂不纳入“两中国”参与者，明确注明两条正统路线尚未整合。
2. 完整兼容（后续可选）：把 `DAY` 设计为第三位海外中华竞争者，重新定义“大清被谁消灭”“谁能宣称统一”“统一后公司体系由谁使用”等状态机。这需要单独设计，不应夹带进文件合并补丁。

### 汉属西洋 `XJB`

汉洲的可释放国家 `XJB` 包含锡兰、南北马达加斯加、印度洋领地和西奈，达到 2 州即可释放；其首都设在北马达加斯加。非洲大明开局持有南北马达加斯加和西奈，因此可能在释放国家界面看到一个本来为汉洲扩张路线准备的国家。

首个实机原型要确认这一入口是否实际向 `MGN` 暴露。若会暴露，兼容补丁应把 `XJB` 的可释放条件限制为 `DAY`、其指定继承者或汉洲专属条件，而不是删除 `XJB`。

## 推荐实现结构

### 阶段 0：固定范围与上游边界

- 将 Workshop 项目 `3464386853` 作为唯一目标，不用模糊标题匹配其他模组。
- 在 `.env.local` 使用例如 `DAYANG_MOD_ROOT` 的机器路径；只在 `.env.example` 记录变量名，不把本机 Steam 路径写进仓库文档。
- 生成前检查目标 metadata 名称、必需文件和上游快照指纹。上游不匹配时应失败退出，不要静默生成可能损坏的兼容包。
- 与对方作者确认兼容补丁的发布和衍生文件许可。未确认前只做本地原型。

### 阶段 1：只做本地可生成的兼容 MVP

建议新增独立工具 `tools/generate_dayang_compat.ps1`，不要改变 `tools/generate_initial_mod.ps1` 的默认产物。

输入：

- 当前 Victoria 3 `GameRoot`。
- 当前非洲大明模组根目录。
- 本地汉洲订阅模组根目录。

生成独立可选模组，例如 `mod/ming_in_africa_dayang_compat`，并要求其拥有最高加载优先级。最小有效载荷为：

1. 合并后的 `common/history/states/00_states.txt`。
   - 以汉洲快照为基底，保留其 17 个新增州、2 个移除州、26 个 `DAY` 开局州和地图对应的省份集合。
   - 复用非洲大明现有转换逻辑，将 92 个非洲州归 `MGN`，保留原 homeland，并加入八种桥接文化 homeland。
   - 保留把埃及非洲之外残余归还奥斯曼的既有处理。
   - 保留非洲大明当前的西藏开局：拉萨、阿里及东喜马拉雅原西藏部分归 `CHI`，并保持 `state_type = unincorporated`；对应中亚建筑与人口作用域继续由非洲大明本体提供。
   - 不手工维护这份大文件。
2. 合并后的 `common/country_formation/00_formable_countries.txt`。
   - 以当前原版为基线。
   - 重放汉洲的 `AOT`、`AST`、`IDN` 差异。
   - 重放非洲大明的 `CHI` 特许公司限制。
   - 先裁决 `FSA` 的非预期差异。
3. 必要时增加 `XJB` 释放条件兼容覆盖。
4. 只有实机证明共享 on_action 丢失时，才增加 on_action 聚合文件；不要预防性扩大覆盖面。

兼容模组的 descriptor 应继续替换 `common/history/states`，并明确依赖两个父模组。推荐加载关系是：汉洲、非洲大明、兼容补丁（兼容补丁最终生效）。启动测试必须验证 Paradox Launcher 对实际排序方向的解释，文档不要只写“放上面/放下面”这种容易歧义的说法。

### 阶段 2：静态验证器

建议新增 `tools/validate_dayang_compat.ps1`，至少验证：

- 输入上游快照符合受支持指纹。
- 合并州历史恰有预期州 key；汉洲当前基线应为 690 个州块。
- `DAY` 有 26 个开局州块，`MGN` 有 92 个，交集为 0。
- 拉萨、阿里及东喜马拉雅原西藏部分均归 `CHI` 且保持未整合，不再生成 `TIB` 开局领土。
- 17 个汉洲新增州存在，东西新几内亚两个旧州不存在。
- 非洲 92 州的 owned province 集合完整且无跨州重复。
- `african_han`、`western_han` 和六种公司桥接文化 homeland 与运行时地区触发器一致。
- `CHI` 保留特许公司限制，`AOT`/`AST` 保持移除，`IDN` 不引用已移除的新几内亚州。
- 两边自定义 tag、顶层对象和 localization key 没有新增撞名。
- 生成器幂等；第二次生成后文件哈希不变。

### 阶段 3：实机验收

建立四个独立播放集：

1. 只启用非洲大明。
2. 只启用汉洲。
3. 两者直载、不加补丁，用来复现已知失败模式。
4. 两者加兼容补丁，用来验收。

兼容播放集的新开局检查：

- 国家选择界面同时存在 `DAY` 与 `MGN`。
- `DAY` 首都和市场首都是惠京，拥有预期 26 州；`MGN` 首都和市场首都是下埃及，拥有预期 92 州。
- 汉洲新增州都有所有者、建筑和人口；非洲大明州的建筑、人口、兵营及桥接文化 homeland 没有丢失。
- 两边的开局日志、事件、法律、兴趣集团命名和每月 on_action 都能触发。
- 大明八家特许公司的建立、领土整合和旧档文化标准化仍工作，尤其测试兰芳与南洋公司。
- 汉洲恢复山河、南洋殖民和 `XJB` 释放入口按兼容设计工作。
- 保存、退出、重载后状态保持。
- 检查 `error.log`，不接受 duplicate state、invalid province、missing state region、unknown country、重复 on_action 覆盖等错误。

### 阶段 4：三方正统设计（独立决策后再做）

只有基础兼容稳定后再决定：

- `DAY` 是否是第三个正统竞争者，还是只作为海外汉人共和国存在。
- `DAY` 消灭 `CHI` 时，`MGN` 的“两中国”日志应关闭、转型还是把对手切换为 `DAY`。
- `MGN` 与 `DAY` 是否允许和平承认、臣属统一或专用战争目标。
- 谁可以使用重建国家、迁都和八家公司体系。
- 双方关于元明清正统的事件文本如何兼容，而不改写对方模组的核心世界观。

这一阶段会触及大量硬编码的 `c:CHI`、胜者判断、日志完成条件和玩家文本，应另写设计稿并征得双方作者认可。

### 阶段 5：发布与维护

- 兼容补丁单独版本化，并记录其支持的非洲大明版本、汉洲 Workshop manifest 和 Victoria 3 版本。
- 上游任一模组更新后先让指纹检查失败，再人工审阅差异并重新生成，不能自动宣称继续兼容。
- README 只增加简短兼容说明和链接；实现细节保留在本文件与 `docs/implementation-map.md`。
- 发布前跑双方各自验证器、兼容验证器和四播放集实机矩阵。

## 未来重新启用时的推荐下一步

若用户以后明确决定继续，第一步只做“阶段 1 + 阶段 2”的本地原型，不发布、不改三方正统叙事。原型成功的硬门槛是：一个新开 1836 存档中 `DAY` 26 州与 `MGN` 92 州同时成立，两边核心日志和每月挂钩都可运行，错误日志无州历史冲突。达到这个门槛后，再决定是否联系对方作者推进公开兼容包与三方路线设计。在收到该明确决定前，本计划保持文档状态，不转化为代码任务。
